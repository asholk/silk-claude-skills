# Obsidian Style

## 1. Загрузи стайлгайд

Перед тем как писать UI-тексты, настройки, команды, уведомления, README или документацию:

1. Открой `https://obsidian.md/ru/help/style-guide` через `WebFetch` (если инструмент отложен — сначала загрузи его через `ToolSearch` `select:WebFetch`). Промпт: «Перечисли все правила полно и с примерами».
2. Для кода плагина дополнительно загрузи `https://docs.obsidian.md/Plugins/Releasing/Plugin+guidelines` — правила UI-текста и API для плагинов.
3. Если страница недоступна, используй краткую выжимку из `reference.md` рядом с этим файлом и скажи об этом пользователю одной строкой.

Загружай один раз за разговор; повторно — только если прошло много времени или пользователь просит.

## 2. Применяй при создании

- **UI-тексты плагина** (`setName`, `setDesc`, `Notice`, команды, кнопки, модалки) — регистр предложения, повелительное наклонение для действий, термины из стайлгайда («заметка», «папка», «сочетание клавиш», «выбрать»).
- **Настройки** — заголовки разделов без слова «настройки», без заголовка верхнего уровня с именем плагина (правило из Plugin guidelines).
- **Команды** — без имени плагина в названии команды (Obsidian добавляет его сам), без сочетаний клавиш по умолчанию.
- **README и документация** — регистр предложения в заголовках, кнопки **жирным**, переходы через →, сочетания клавиш вида `Ctrl+Z` без пробелов, выносные блоки и `description` до 150 символов по правилам гайда.
- **Значки** — Lucide (`setIcon(el, "lucide-name")` / имя без префикса в API).

Язык текста — тот, на котором пишет пользователь или уже написан плагин; правила гайда применяй к нему.

## 3. Проверь

Перед завершением пройди по созданным строкам и исправь отклонения от гайда. В ответе отдельно не перечисляй применённые правила — только если пользователь спросит или если пришлось отступить от гайда (тогда одной строкой: что и почему).
